Overview

Architecture that keeps connectors consistent

The Core owns the reusable integration model. A provider connector supplies the external API client and platform workflows, while administrators work with one familiar configuration and monitoring experience.

External platform→Provider connector→eCommerce Core→OCA queue_job→Odoo records

Instance

External system, company scope, credentials, provider capabilities, and a dedicated queue user.

Store

Website, store view, warehouse, currency, automation, batch sizes, and scheduling for one sales channel.

Mappings

Persistent links for products, variants, categories, customers, orders, invoices, payments, shipments, refunds, carriers, payment methods, and inventory sources.

Sync state

Per-Store and per-resource cursors, last success, last failure, and incremental replay controls.

Queue orchestration

Bounded coordinator and child jobs with channels, retry policies, deduplication keys, and progress runs.

Observability

Events, actionable issues, mapping status, and queue state make failures visible instead of hiding them in logs.

Important: this module does not connect to an external platform by itself. It is the shared foundation and dependency for a provider connector such as Magento Connector for Odoo.

01

Instances and Stores

Separate external systems from the sales channels inside them. An Instance holds credentials and provider capability; a Store holds the external scope, warehouse, currency, automation, and scheduling settings.

  • Company-scoped configuration and record rules
  • Manager-only credential access
  • Per-Store queue scheduling and batch sizes
  • Test Connection and Preflight from the form
02

Store synchronization

Run supported catalog, order, inventory, shipment, and finance operations from a Store. Work is queued through OCA queue_job and reports progress back to the Store.

  • Import, Export, and Update operations where supported
  • Bounded batches and deduplicated queue identities
  • Safe replay through existing mappings
  • Visible progress and structured issues
03

Product content and Storefront fields

Core adds provider-neutral content fields used by connectors: short description, URL key with manual override, SEO metadata, and per-media alt text. URL keys are generated from the product name until a user edits them; manual values are preserved across renames.

  • Short and long eCommerce descriptions
  • Editable SEO fields with generated URL keys
  • Media gallery alt text
  • Provider-neutral fields shared by connectors
04

Auditable mappings

Store-scoped mappings preserve the external identity required for safe repeat synchronization. A single mapping layer links catalog, commercial, and operational records.

05

Background work built for operations

Slow API calls do not block the web client. Coordinator jobs split long work into bounded child jobs, while deterministic identity keys prevent accidental duplicate enqueueing.

User Guide

From installation to the first synchronization

  1. Configure an Instance. Open eCommerce → Configuration → Instances. Enter the external URL, credentials, company, and queue user, then click Test Connection.
  2. Create a Store. Open eCommerce → Configuration → Stores. Select the Instance, external scope, warehouse, company, currency, and automation settings. Run Test / Preflight.
  3. Set synchronization intervals. Open the Store's Scheduling tab and configure order, customer, catalog, category, inventory, shipment, and finance intervals plus batch sizes.
  4. Configure initial mappings. Use eCommerce → Configuration for inventory sources, payment methods, delivery carriers, and provider-specific mappings. Use Sync Now for connector-supported operations.
  5. Import data. Run provider actions for categories and catalog, then customers, orders, inventory reconciliation, shipments, and finance as supported. Review events, issues, and queue states after each run.
  6. Export and update categories and products. Use the Store synchronization wizard or the product form's Sync to eCommerce action. Choose Export for the first synchronization and Update for existing mappings.
Retry-safe by design: mappings, queue identity keys, and synchronization state let the same operation be repeated without creating duplicate external records.
System Requirements

Prepare the Odoo environment

ComponentRequirement
Odoo modulesBase, Mail, Sales Management, Stock, Accounting, Delivery, Website Sale, and Queue Job.
OCA queue_jobDownload from github.com/OCA/queue. Add the repository root to addons_path, update the Apps list, then install Queue Job.
Queue configurationRun a queue runner with at least workers = 2. Load server_wide_modules = web,queue_job, restart Odoo, and verify pending jobs move to Done.
Provider connectorInstall a compatible connector such as Magento Connector for Odoo. Magento-specific setup is documented in that module.
PermissionsAssign eCommerce User, Operator, or Manager access as appropriate. Configure a dedicated queue user with access to the Instance company.
Core is not a standalone connector: it does not contact an external platform without an installed provider module.
  1. Place odoo_ecommerce_integration in your addons path and update the Apps list.
  2. Install eCommerce Integration Core.
  3. Install and configure OCA Queue Job.
  4. Install a compatible provider connector.
