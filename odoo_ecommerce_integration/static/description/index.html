eCommerce Integration Core

One operating layer for every eCommerce connection.

A provider-neutral foundation for Instances, Stores, mappings, synchronization jobs, and operational visibility in Odoo.

The Core does not call an external platform by itself. It provides the shared configuration, mapping, queue, and monitoring layer used by a compatible connector.

Use it with Magento Connector for Odoo or another provider module.

Overview

A shared foundation, not another connector.

A connector supplies the external API and platform-specific workflows. The Core supplies the parts every connector needs: company-scoped Instances, Store scopes, durable mappings, background jobs, synchronization state, and clear issue tracking.

01

Instances define access. Stores define scope.

An Instance holds the external URL, credentials, provider capabilities, company, and queue user. A Store holds the sales-channel scope, warehouse, currency, automation settings, and synchronization schedule.

  • Credentials stay behind manager permissions.
  • Stores remain scoped to one company and Instance.
  • Test Connection and Preflight make configuration problems visible early.
02

Run synchronization from one familiar wizard.

Choose an operation, the data type, and target Stores. The connector checks capability and queues only supported work.

  • Import, Export, and Update where supported by the provider.
  • Bounded batches and deduplicated queue identities.
  • Existing mappings make repeat runs safe.
03

Prepare product content once.

Provider-neutral fields keep storefront copy together with the product: short description, URL key, SEO metadata, and media alt text.

  • URL keys generated from the product name.
  • Manual URL keys preserved across renames.
  • Description, SEO, and media text shared by connectors.
04

Export or update a product from its form.

Select target Stores, choose Export or Update, and queue the work without leaving the product.

  • Export creates the first external mapping.
  • Update refreshes an existing mapped product.
  • Mapping status is shown before you queue the job.
Mappings & observability

Every external record can be traced back.

05

Mappings protect repeat synchronization.

Store-scoped mappings connect Odoo records with stable external identities: products, variants, categories, customers, orders, invoices, payments, shipments, refunds, carriers, payment methods, and inventory sources.

  • Unique identities prevent duplicate imports.
  • Sync state and last-sync time stay visible.
  • Mappings remain auditable after the job completes.
06

Long-running work stays in the background.

Coordinator jobs split large imports into bounded child jobs. Retries, deduplication keys, and queue channels keep operations predictable.

  • Dedicated channels for catalog, orders, inventory, shipments, and finance.
  • Retry policies for transient failures.
  • Execution state remains inspectable.
Setup guide

From installation to a controlled first sync.

  1. Install OCA queue_job. Download the Queue Job addon from github.com/OCA/queue, add the repository root to addons_path, update the Apps list, and install Queue Job.
  2. Configure the queue runner. Set workers = 2 and server_wide_modules = web,queue_job, restart Odoo, and confirm a test job moves from pending to done.
  3. Install the Core and a connector. Install eCommerce Integration Core, then the provider connector you use. The Core alone does not contact an external platform.
  4. Create an Instance. Open eCommerce → Configuration → Instances. Enter the external URL, credentials, company, and queue user, then click Test Connection.
  5. Create a Store. Open eCommerce → Configuration → Stores. Choose the Instance, external scope, warehouse, currency, and automation settings, then run Test / Preflight.
  1. Set synchronization intervals. In the Store's Scheduling tab, configure order, customer, catalog, category, inventory, shipment, and finance intervals plus batch sizes.
  2. Prepare initial mappings. Use eCommerce → Configuration for inventory sources, delivery carriers, payment methods, and connector-specific mappings.
  3. Import initial data and create mappings. Run connector actions for categories, catalog, customers, orders, inventory, shipments, and finance as supported. Confirm mappings and issues after each run.
  4. Export or update categories and products. Use Sync Now on the Store or Sync to eCommerce on a product. Choose Export for a first sync and Update for existing mappings.
  5. Monitor operations. Review Monitoring → Queue Jobs, Synchronization Issues, and Synchronization States after significant imports or exports.
Requirements

What the Core needs.

ComponentRequirement
Odoo modulesBase, Mail, Sales Management, Stock, Accounting, Delivery, Website Sale, and Queue Job.
QueueOCA queue_job with a running queue runner and a dedicated queue user.
ProviderA compatible connector. The Core has no built-in external API client.
AccesseCommerce Manager for configuration and credentials; Operator for synchronization; User for read-only access.

Limitations: the Core is not a standalone connector. Platform-specific capabilities, external field mappings, and provider workflows depend on the installed connector. There are no built-in webhooks, RMA workflows, or external API calls in this module.
